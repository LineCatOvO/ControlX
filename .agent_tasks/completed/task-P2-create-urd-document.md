**内容规划**：

```markdown
# ControlX 用户需求文档

## 1. 文档定位

本文档描述远程赛车输入控制系统的用户角色、使用场景和用户故事。

## 2. 用户角色

### 2.1 主要用户：赛车游戏玩家

| 特征 | 描述 |
|------|------|
| 目标 | 通过安卓设备远程控制赛车游戏 |
| 场景 | 单设备本地运行 |
| 技术水平 | 普通用户，无需专业技术知识 |
| 期望 | 简单易用、稳定可靠 |

### 2.2 次要用户：布局创作者

| 特征 | 描述 |
|------|------|
| 目标 | 创建、分享操作布局配置 |
| 场景 | 调整控制映射、优化操控体验 |
| 技术水平 | 略有技术理解 |
| 期望 | 灵活的布局编辑工具 |

## 3. 使用场景

### 场景 1：日常游戏控制

用户使用安卓设备的触控界面，控制 Windows 上的赛车游戏。

前置条件：
- 安卓设备已安装客户端应用
- Windows 已安装服务端
- ViGEmBus 驱动已安装

用户操作：
1. 启动客户端应用
2. 选择或创建操作布局
3. 启用控制
4. 开始游戏操控

期望结果：
- 游戏响应控制输入
- 控制延迟可接受
- 控制行为与操作意图一致

### 场景 2：布局编辑与调整

用户需要调整控制映射或创建新的操作布局。

用户操作：
1. 进入布局编辑模式
2. 调整操作区域位置和大小
3. 修改控制映射参数
4. 保存布局

期望结果：
- 编辑即时生效
- 不中断当前控制运行
- 编辑结果可预览

### 场景 3：布局分享与导入

用户希望分享自己的操作布局，或使用他人的布局。

用户操作：
1. 导出当前布局为文件
2. 分享给其他用户
或
1. 接收他人布局文件
2. 导入布局
3. 应用布局

期望结果：
- 布局可分享、可导入
- 导入后布局正确生效

## 4. 用户故事

### US-01：基本控制

作为一个赛车游戏玩家，
我想要通过安卓触控界面控制游戏，
以便在不使用物理手柄的情况下玩游戏。

验收标准：
- 触控操作能生成控制输入
- 游戏响应控制输入
- 控制延迟在可接受范围内

### US-02：布局管理

作为一个用户，
我想要管理多个操作布局，
以便在不同游戏中使用不同的控制配置。

验收标准：
- 可以创建、删除、切换布局
- 切换布局即时生效
- 布局数据持久保存

### US-03：布局编辑

作为一个布局创作者，
我想要灵活编辑操作布局，
以便优化我的控制体验。

验收标准：
- 可以添加、删除操作元素
- 可以调整位置和大小
- 可以修改控制映射
- 编辑过程可预览效果

### US-04：安全回退

作为一个用户，
我想要系统在异常情况下安全清零，
以便不会产生残留控制输入。

验收标准：
- 断连后控制清零
- 异常后控制清零
- 禁用后控制清零

## 5. 非功能需求

| 类别 | 需求 |
|------|------|
| 性能 | 控制更新频率 ≥125Hz |
| 可用性 | 界面简单直观 |
| 可靠性 | 无残留控制输入 |
| 安全性 | 异常情况安全回退 |

## 6. 参考

- docs/SRS.md - 软件需求规格
- README.md - 项目介绍
```
