# 服务端日志重新设计方案

## 问题分析
当前服务端日志存在以下问题：
1. 每次输入状态更新时都打印完整的当前状态
2. 大量重复日志，影响可读性
3. 缺乏事件驱动的日志记录方式
4. 日志中包含冗余信息

## 设计目标
1. 只记录状态变化的事件
2. 减少重复日志
3. 提高日志的可读性和有用性
4. 保留关键的状态变化信息
5. 区分不同类型的事件

## 具体修改方案

### 1. 键盘执行器 (`keyboard.ts`)
- **修改**：在 `updateKeyboardState` 方法中，只在按键状态发生变化时记录日志
- **保留**：按键按下和释放事件的日志
- **移除**：重复的完整状态日志
- **优化**：记录具体的按键变化，而不是完整的按键集合

### 2. 鼠标执行器 (`mouse.ts`)
- **修改**：在 `applyState` 方法中，只在鼠标状态发生变化时记录日志
- **保留**：鼠标事件的日志
- **移除**：每次调用都打印的完整状态日志
- **优化**：记录具体的鼠标动作，如移动、点击等

### 3. 摇杆执行器 (`joystick.ts`)
- **修改**：在 `updateAxes` 和 `submitFullState` 方法中，只在状态发生变化时记录日志
- **保留**：轴值变化、按钮状态变化的日志
- **移除**：每次调用都打印的完整摇杆状态日志
- **优化**：记录具体的轴值变化和按钮状态变化

### 4. 状态存储 (`stateStore.ts`)
- **修改**：在 `storeState` 方法中，减少重复的状态存储日志
- **保留**：无效状态、无效序列号的错误日志
- **优化**：只在状态成功存储时记录简要日志

### 5. 输入处理器 (`input.ts`)
- **修改**：在 `handleInput` 方法中，优化日志记录
- **保留**：客户端信息、ACK 发送成功/失败的日志
- **优化**：减少重复的日志记录

## 预期效果
1. 日志量显著减少，不再有大量重复的完整状态日志
2. 日志只记录状态变化的事件，更有价值
3. 日志可读性提高，更容易理解系统行为
4. 更容易定位问题和分析系统性能
5. 保留了关键的状态变化信息

## 实施步骤
1. 首先修改键盘执行器的日志记录
2. 然后修改鼠标执行器的日志记录
3. 接着修改摇杆执行器的日志记录
4. 最后修改状态存储和输入处理器的日志记录
5. 测试修改后的日志输出效果

## 测试方法
1. 启动服务端
2. 连接客户端并发送输入状态
3. 观察日志输出，确保只记录状态变化的事件
4. 检查日志的可读性和有用性

## 风险评估
1. **风险**：可能遗漏某些重要的状态变化信息
   **对策**：仔细设计日志记录逻辑，确保关键事件都被记录
2. **风险**：修改后可能影响调试
   **对策**：保留必要的调试信息，使用不同的日志级别区分
3. **风险**：修改过程中可能引入新的bug
   **对策**：仔细测试每一个修改，确保不影响系统功能

## 技术要点
1. 使用状态比较来判断是否需要记录日志
2. 记录具体的事件类型和变化内容
3. 使用合适的日志级别
4. 保持日志的简洁性和可读性
5. 避免重复记录相同的信息
